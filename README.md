# BUSI replication — Boudraa et al. (2026)

Replication of *"Deep learning-based breast cancer detection in ultrasound images:
Integration of YOLO, MedSAM, and Optuna hyperparameter optimization"*,
Intelligence-Based Medicine 15 (2026) 100434, on the BUSI dataset. Thesis work.

Headline target: accuracy 0.8803 (103/117 test images), macro-F1 0.8821,
malignant-F1 0.8254 for yolov10b + Optuna hyperparameters (+ MedSAM, which changes nothing).

## The whole thing is one notebook

`busi_replication.ipynb` runs end to end on Kaggle (GPU T4 x2, ~7–8 h) and
explains every step in place: dataset construction, split, near-duplicate scan,
hyperparameters (Table 2), training of all 11 variants + the ablation, MedSAM
scoring, Tables 3 & 4 with deltas against the paper, gates, seed variance,
leakage-corrected results, figures.

Run it:

1. Kaggle → New Notebook → File → Import `busi_replication.ipynb`.
2. Add Input → Datasets → *Breast Ultrasound Images Dataset* (`aryashah2k/breast-ultrasound-images-dataset`).
3. Settings → Accelerator **GPU T4 x2**, Internet **On**.
4. `SMOKE = True` → Run All (~15 min) to prove the plumbing.
5. `SMOKE = False` → Save Version → **Save & Run All (Commit)**. Output lands in the version's `/kaggle/working`.
6. If the time budget skipped runs: Add Input → Your Work → this notebook's output, commit again. Finished runs are reused.

## Design decisions

- **No Optuna rerun.** 30 trials × 50 epochs × 11 variants > 150 GPU-hours. Table 2
  publishes the winners; training with them reproduces every result. A reduced search
  is a separate, later experiment.
- **`preds.json` is the contract.** Every box on every test image is stored once; all
  metrics, tables and fusion variants are recomputed from it without a GPU.
- **Image label = class of the best box** (confidence, or confidence × MedSAM predicted
  IoU). The paper never states this; it is the only reading consistent with its Table 4.
- **MedSAM preprocessing is a first-order effect.** The official `MedSAM_Inference.py`
  (1024×1024 squash, min-max to [0,1]) and the HF checkpoint's `SamProcessor` config
  (aspect-preserving pad, ImageNet mean/std) disagree. On 20 test images with GT-box
  prompts: official 0.76 Dice, HF 0.81, pad+min-max 0.78, **squash + ImageNet 0.91**.
  The notebook runs §4.3 for all four and uses a recipe fixed a priori (squash +
  ImageNet) for the fusion. `results/medsam_standalone_hf_processor.json` is the
  earlier full-117-image pass with the HF default (Dice 0.83), kept as evidence.

## What the paper gets wrong (verified)

- **MedSAM contributes nothing.** In the paper's own Table 4, Config D − Config B is
  0.0000 (yolov10b), −0.0096 (yolov10n), −0.0091 (yolo11s). Multiplying every box by a
  positive scalar cannot change the arg-max unless boxes of different classes nearly tie.
- **Two different "IoU"s.** §4.3 reports true IoU vs ground-truth masks; the fusion can
  only use SAM's predicted-IoU head (Fig. 3 shows IoU 0.77 with Dice 0.00 on a normal image).
- **Test-set leakage.** BUSI contains the same scan re-cropped many times. With the
  paper's split recipe, 43 of 117 test images (37 %) have a near-duplicate in train/val,
  9 of them at perceptual-hash distance 0; one pair (`benign (433)` / `malignant (145)`)
  is byte-identical with different labels. The paper never checks. The notebook scores
  the clean and contaminated halves of the test set separately.
- **Normal = full-image box**, which makes it trivially detectable (100 % recall).
- Provenance: BUSI is from Baheya Hospital, Cairo (Al-Dhabyani et al. 2020), not Shiraz;
  Ultralytics weights are COCO-pretrained, not ImageNet; Table 2's `imgsz=416` for
  yolov10l is outside the search space §3.3 claims; Table 3's training-time column is
  non-monotonic in model size (early stopping) and carries no information.
